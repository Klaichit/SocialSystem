Routine ยิงเข้ามาทุกวัน 07:00 (เวลาไทย) เป็น session ใหม่ที่ไม่มีความจำจากเมื่อวาน

## หลักที่ต้องยึด

- **ภาพไม่ผ่านตัวโมเดล** PNG ใบละ ~60KB ถ้าส่ง base64 เข้า Drive จะกิน ~35k tokens ต่อใบ
  จนรอบเช้าทำไม่จบ ภาพจึงไป Drive ทางเดียวคือ commit เข้า repo แล้วเครื่อง msi `git pull`
  ลงโฟลเดอร์ที่ Drive desktop ซิงก์อยู่ Drive ได้แค่ไฟล์ข้อความ
- **ห้ามแตะ Notion** บอร์ดเป็นของ DK รอบเช้าอ่านอย่างเดียว
  กันทำซ้ำด้วย `automation/state/done.json` ฝั่งเราแทน
- **ห้ามแตะ `board-images`** ของหน้า Content Hub artifact (กฎเดิมจาก skill `24senergy-board-sync`)
- ถ้าไม่มีแถวใหม่ ให้จบรอบเงียบ ๆ ไม่ต้อง commit ไม่ต้องรายงาน

## ขั้นตอน

### 1. ถามว่ามีอะไรต้องทำ

query `collection://6a2e052d-8552-4bb9-8ca7-2d7b86402a17` ด้วย notion-query-data-sources:

```sql
SELECT url, "ชื่อคอนเทนต์", "ประเภท", "หมวดข่าว", "สัดส่วนภาพ", "ข้อความบนภาพ",
       "สรุปภาษาไทย", CTA, "ร่างแคปชัน", "แหล่งข่าว", "Factual Guardrails",
       "date:กำหนดเผยแพร่:start" AS pubdate
FROM "collection://6a2e052d-8552-4bb9-8ca7-2d7b86402a17"
WHERE "DK อนุมัติ" = '__YES__'
  AND ifnull("Render Status",'') != 'rendered'
  AND ifnull("ขั้นตอน",'') NOT IN ('พักไว้','เผยแพร่แล้ว')
ORDER BY pubdate
```

เซฟผลลัพธ์เป็น `rows.json` ใน scratchpad

### 2. ตั้งโครง

```bash
python3 automation/plan.py <rows.json> outputs/
```

ได้ `outputs/YYYY-MM-DD หัวข้อ/job.json` ต่อโพสต์ (ชื่อโฟลเดอร์ตรงกับที่ใช้ใน
`E:\MyDrive\24SEnergy\Facebook\` อยู่แล้ว) แถวที่ทำไปแล้วจะถูกข้ามอัตโนมัติ

### 3. เกลาข้อความ — ข้อนี้สำคัญที่สุด

**อ่านหัวข้อ "กฎการออกแบบเทมเพลต" ใน `CLAUDE.md` ก่อน** กฎในนั้นมีผลเหนือไฟล์นี้

`plan.py` เลือกชุดเทมเพลตตามประเภทและดูดข้อความมาให้แบบหยาบ ๆ เท่านั้น
อ่าน `job.json` แล้วเขียนใหม่ให้เป็นคอนเทนต์จริง:

- **พาดหัวรองห้ามซ้ำเนื้อความ** และห้ามตัดค้างกลางวลี
- สไลด์หนึ่งใบ = ความคิดเดียว ยาวเกินให้ตัด ไม่ใช่ย่อฟอนต์
- **ห้ามใส่วันที่ลงภาพ** ช่องขวาของ `meta` ใช้บอกหมวด / รุ่น / เทคโนโลยีแทน
- `foot` ใบที่ยังมีต่อ ปล่อยค่าเริ่มต้น (`ดูต่อ →`) ใบ CTA ใช้ `24senergy.co.th`
- ตัวเลขและสเปกใช้ mono เสมอ — โทน B2B-industrial ไม่ใช่เพจไลฟ์สไตล์
- จังหวะพื้นหลัง: ใบเปิดเข้ม → ใบเนื้อหาขาว → ใบปิดเข้มอีกครั้ง
- `m1` (ข้อควรระวัง) `plan.py` ปล่อยว่างไว้ให้เติมเอง ดึงจากท่อน "ข้อควรระวัง" ใน ร่างแคปชัน
- ถ้าแถวมี `Factual Guardrails` ห้ามเขียนอะไรเกินกว่านั้น อย่าเดาตัวเลขเอง
- เปลี่ยนเทมเพลตได้ตามใจถ้าอันที่เลือกมาไม่เข้ากับเนื้อหา ดูรายการเต็มใน
  `builder/templates.json` (`blocks` คีย์คือลำดับบล็อกในเทมเพลต เริ่มที่ 0)
- ทุกใบต้องมี `foot` ใบสุดท้ายต้องเป็น CTA

### 4. เรนเดอร์

```bash
node automation/render.mjs "outputs/<โฟลเดอร์>/job.json" "outputs/<โฟลเดอร์>"
```

ผลลัพธ์รายงาน `overflow` ต่อใบ **ถ้ามีใบไหน `true` ต้องตัดข้อความแล้วเรนเดอร์ใหม่**
ห้าม commit ภาพที่ล้น เปิดดูภาพปกสักใบเพื่อเช็คสายตาก็พอ ไม่ต้องเปิดทุกใบ (ใบละ ~1.5k tokens)

### 5. แคปชันกับแฮชแท็ก

เขียน `outputs/<โฟลเดอร์>/แคปชัน.txt` ประกอบด้วย ร่างแคปชันจาก Notion, CTA,
ลิงก์ข่าวต้นฉบับ และแฮชแท็กที่สร้างจาก หมวดข่าว + กลุ่มเป้าหมาย + ประเภท + แบรนด์
(กติกาเดียวกับบอร์ด)

### 6. Commit และ push

```bash
git add outputs/ automation/state/done.json
git commit -m "ภาพ carousel: <หัวข้อ>"
git push -u origin main
```

แล้วบันทึกกันทำซ้ำทีละโพสต์:

```bash
python3 automation/plan.py --mark "<notion url>" "<ชื่อโฟลเดอร์>" <จำนวนสไลด์>
```
